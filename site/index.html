Customer-facing chatbots that follow your rules.

Describe a bot in plain English, or write its YAML yourself: what it's for, what it asks, its rules and when it hands over to a person. One open-source runtime enforces all of it in code, not in a prompt.

Make a bot from a description Fork on GitHub 
agent: support-assistant
charter: "Help customers with orders and returns. Out of scope: legal advice."
tools: [knowledge_search]
flow:
  - greet_consent
  - form_fill:
      fields:
        - {name: order_number, ask: "What is your order number?", expect: "An order number"}
        - {name: issue, ask: "What went wrong?", expect: "A short description", optional: true}
guardrails: {input: [prompt_injection], output: [pii, no_legal_advice]}
handoff: {when: [user_request, max_reasks]}

Why it's needed

A bot that is only a prompt works in a demo and drifts in production. When it has a job to finish (take an order number, book a slot, collect an application), the model is asked to remember the steps, count its own attempts, stay in scope and know when to stop. It does that most of the time. yachat moves those decisions into code and leaves the model to read and phrase.

A prompt-only botWith yachat
Skips a question, or moves on with an answer it couldn't use Steps are code. A form isn't done until every field passes its check; the next step is decided by the runtime.
Asks the same thing forever, or gives up at random Counting lives in code. Re-asks, digressions and budgets have limits; at the limit it hands over to a person, with the conversation so far.
Promises a refund, gives legal advice, leaks a phone number Rules and guardrails. Plain-language rules apply on the turns they fit; input and output checks run on every reply.
Calls any tool with anything the model makes up One tool gateway. An allow list per bot, timeouts, a circuit breaker; tool output is treated as untrusted.
A prompt edit changes every live chat, and nobody reviewed it A file you can review. Each bot is one YAML policy, versioned with rollback; a conversation stays on the version it started on.
"It seemed fine when I tried it" Tested from the policy. Test sets are generated from the YAML; a stronger model reviews trial chats and proposes fixes.

Who uses what

Support and ops teams

Describe the bot in plain English, read back what it will do, ask for changes the same way. No YAML needed.

Developers

Add a tool, step, guardrail or channel as one decorated Python function, or connect an MCP server. Run many bots on one runtime.

Reviewers

Read one file per bot, see why each reply was chosen, and check the audit log, outcomes and model cost.

Not the right tool for a free-form assistant, multi-agent research workflows, or if you need stable APIs today: yachat is alpha. How it compares with Parlant, Rasa, LangGraph and Botpress.

Any model

Anthropic or anything litellm reaches; small models for routine turns, a stronger one where it pays off.

Any channel

A website widget, WhatsApp, SMS, Slack and phone; each channel keeps its own limits and opt-out rules.

Self-hosted

Runs on a laptop with only a model key, or in Docker with Redis and Postgres. Apache-2.0.

Run it yourself

git clone https://github.com/pnrajan/yachat && cd yachat
./setup.sh                # installs what's missing, asks for your model key
scripts/try.sh            # the console, with a sample bot

Needs macOS, Linux or WSL and a model key; setup.sh installs the rest. Or run it all in Docker with scripts/local.sh up. Quickstart · Every YAML key
